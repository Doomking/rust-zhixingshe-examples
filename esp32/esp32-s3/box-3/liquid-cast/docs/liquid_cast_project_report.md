# LiquidCast: 基于 Rust 与 ESP32-S3 的高性能流媒体播放器项目全记录

## 一、 项目背景
LiquidCast 是一个旨在探索 ESP32-S3 极致性能的开源项目。通过 Rust 语言的高安全性与零成本抽象，我们实现了一个能够通过 Wi-Fi 实时接收并播放来自 Mac/PC 端音视频流的媒体播放器。该项目不仅展示了硬件加速 JPEG 解码、DMA 高速渲染，还深入探讨了嵌入式场景下的 A/V 同步与复杂网络协议处理。

---

## 二、 核心技术选型
在立项之初，我们对性能与开发效率进行了权衡，最终确定了以下技术栈：

1.  **编程语言：Rust**
    *   **理由**：内存安全保证，彻底避免了嵌入式开发中常见的悬垂指针和内存泄漏；极高的并发安全性，使得处理多线程音视频解复用变得得心应手。
2.  **硬件平台：ESP32-S3 (ESP32-S3-BOX-3)**
    *   **优势**：双核 240MHz 处理器，内置硬件 JPEG 解码器，支持 Octal SPI PSRAM，是实时流媒体处理的理想选择。
3.  **媒体格式：MJPEG + PCM**
    *   **理由**：MJPEG 虽然压缩率不如 H.264，但对计算资源要求极低，配合 ESP32-S3 的硬件解码器可轻松达到 20FPS+；PCM 音频无压缩损耗，方便与 I2S 直接对接。
4.  **传输协议：自定义 LiquidProtocol (TCP)**
    *   **理由**：在局域网环境下，TCP 配合 Magic Word 校验能提供比 UDP 更稳定的时钟基准和数据完整性。

## 三、 系统架构设计
项目采用典型的 **服务端 (Server) - 客户端 (Client)** 模型：

### 1. Mac 服务端 (mac-server)
*   **引擎**：集成 FFmpeg，负责将任意格式的 MP4 实时转码为 MJPEG 序列和 PCM 音频块。
*   **调度**：采用 `tokio` 异步运行时，每个连接拥有独立的视频、音频、控制和心跳任务。
*   **节流控制**：为了防止服务端“过快推流”压垮客户端缓冲区，我们实现了基于时间戳的**高精度节流器**，确保推流速率严格匹配现实时间。

### 2. ESP 客户端 (esp-client)
*   **多线程协作**：
    *   `tcp-client` 线程：负责协议解包、Magic Word 对齐、数据分发。
    *   `audio-i2s` 线程：作为**主时钟 (Master Clock)**，驱动 I2S 播放。
    *   `main` 线程：负责视频解码与 DMA 渲染，并根据音频时钟进行动态 A/V 同步。
*   **零拷贝路径**：视频数据直接从 JPEG 解码器写入显示器的显存缓冲区，消除了中间拷贝，极大释放了 PSRAM 性能。

## 四、 核心实践与优化记录

### 1. 解决内存碎片：零分配解码 (Zero-Allocation)
*   **挑战**：早期版本每秒进行几十次 `Vec` 分配，导致 PSRAM 迅速碎片化，运行数分钟后崩溃。
*   **实践**：重构解码器接口，通过 `VideoOutput` Trait 获取预分配好的 Backbuffer 引用，实现“直接解码至显存”。

### 2. A/V 同步算法：以音为准
*   **挑战**：网络抖动会导致视频时快时慢，出现声画不同步。
*   **实践**：在客户端建立音频主时钟。视频帧在渲染前会对比自己的 Timestamp 与当前音频播放进度：
    *   **过晚**：直接丢弃，赶上进度。
    *   **过快**：短暂休眠，等待音频。

### 3. 网络鲁棒性：Magic Word 对齐
*   **挑战**：TCP 流如果出现 1 字节位移，会导致整个协议解析崩溃。
*   **实践**：在协议层引入 `LC` (0x4C, 0x43) 魔数。当解析失败时，系统会自动在流中搜索该标志位重新对齐，保证了长时间运行的稳定性。

### 4. 消除周期性卡顿：服务端节流
*   **挑战**：推流过快导致 ESP32 缓冲区满，TCP 窗口关闭引发 Head-of-Line Blocking。
*   **实践**：在服务端增加 `target_time` 检查，只有在真实时间到达帧时间戳时才发送数据。

## 五、 项目总结与感悟
LiquidCast 项目证明了 Rust 在硬核嵌入式领域的强大竞争力。从底层驱动到上层协议栈，Rust 提供的类型安全让我们可以大胆地进行重构与性能压榨，而不必担心深夜在调试器里找 Segfault。

本项目对于希望深入了解 **ESP-IDF、DMA 渲染、FFmpeg 集成以及流媒体同步** 的开发者具有极高的参考价值。
